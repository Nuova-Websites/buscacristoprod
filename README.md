# Busca Cristo

Static site for the Barcelona Mission outreach. Pages are generated from templates.

## Editing

- **Edit `src/`, not the root `.html` files.** The root pages are generated and get overwritten.
  - `src/pages/**` — page content (mirrors the site layout; front matter sets `title`, `description`, etc.)
  - `src/partials/` — shared nav, footer and social icons
  - `src/layouts/base.html` — `<head>` and page skeleton
  - `src/site.json` — site-wide values, including the social media URLs
- Styles: `css/styles.css`. Scripts: `js/site.js` (all pages), `js/home.js` (home page only).

## Build

```bash
npm run build
```

Writes the generated pages next to `src/` (same paths as before), so hosting is unchanged. Commit the generated files too.

## Languages

The site is built in 5 languages: Spanish (default, at the site root) and English, French, Portuguese and Catalan in `/en/`, `/fr/`, `/pt/`, `/ca/`.

- **Spanish is the source.** Write and edit pages in `src/pages/` in Spanish only.
- **Translations** live in `src/i18n/<lang>/*.json` as `{ "id": "translated text" }`. The ids come from `src/i18n/catalog.json`, which the build regenerates from the Spanish text. If you change or add Spanish text, the build falls back to Spanish for that string and reports it as missing.
- **Find what's missing:** `node build.mjs --missing en` prints every untranslated string for a language (use `fr`, `pt`, `ca` likewise). `node build.mjs --strict` fails the build if anything is missing.
- **Inline markup** inside a text (links, bold) appears as `<t1>…</t1>` markers in the catalog. Keep the markers in the translation; the real tags and links are restored by number.
- **JavaScript messages** (form errors, "Sending...") are in `src/i18n/js.json`.
- **Switching:** the picker in the menu saves the visitor's choice. With no saved choice, someone landing on a Spanish page is sent to the first of their browser languages that the site supports. Links to a language page (e.g. a shared `/en/` link) are never redirected away.

## Contact form

The form on the home page posts to a Google Apps Script web app that appends a row to a Google Sheet. The web app URL is `API_URL` at the top of `js/home.js`. The form needs the consent checkbox ticked (linking to the privacy page), and either an email or a phone number. The visitor's page language is saved with each message.

## Search engines (SEO)

- `sitemap.xml` and `robots.txt` are **generated by the build** — don't edit them by hand. The sitemap lists every page in every language, with each page's translations linked (hreflang). `robots.txt` allows all crawlers and points to the sitemap.
- Every page's `<head>` also carries hreflang links to its translations. All of these use the site address `SITE_URL` at the top of `build.mjs` (`https://www.buscacristo.org`).
- After the site is live, add it to Google Search Console and submit `https://www.buscacristo.org/sitemap.xml`.

## Media

- Photos are self-hosted in `img/photos/` as WebP (nothing is hotlinked from other sites).
- The home page hero video is `video/hero.mp4` (720p, no audio, about 5 MB) and its poster, the video's first frame, is `img/hero-poster.jpg`. Keep videos short and compressed.

## Hosting and publishing

- Hosted on GitHub Pages from the `main` branch, root folder. The custom domain is `www.buscacristo.org` (the bare `buscacristo.org` redirects to it), set by the `CNAME` file. **Never delete `CNAME`**, or Pages will drop the domain.
- **Who does what:**
  - **Wix** is where the domain `buscacristo.org` is registered (bought and renewed there).
  - **Cloudflare** runs the redirects (for example the old language addresses such as `en.buscacristo.org`, which send visitors to the matching language on the main site).
  - **GitHub** hosts the site itself (GitHub Pages).
  - The DNS records that point the domain at GitHub (the `A` records for the bare domain and the `www` CNAME to `nuova-websites.github.io`) must stay in place. If you change DNS, check that the site still loads at `https://www.buscacristo.org`.
- To publish a change: edit `src/`, run `npm run build`, then commit everything (source and generated files) and push to `main`. GitHub Pages deploys automatically within a minute or two.
- Run `git pull` before pushing; the Pages settings page can add commits to the repository (for example for `CNAME`).
